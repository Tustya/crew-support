# Допущения безопасности

Рабочий пилот заблокирован CR-01…CR-05: нет схемы КШД, стабильных идентификаторов, доказательства утренней/вечерней отправки, протокола почты и корпоративного SSO.

## Fail-closed

- `AUTH_MODE` в production только `disabled`. Заголовок `X-Dev-Subject` читается лишь при `mock` вне production. `X-Role`, `role` и `actor` из запроса не назначают права. Роль берётся из `app_users`.
- `SOURCE_ADAPTER` в production только `disabled`. `sample` — синтетические фикстуры, не Aviabit.
- `MAIL_ADAPTER` в production только `disabled`. `scripted` разрешён в тесте. Исход `X-Test-Mail-Outcome` вне scripted/не-production игнорируется. `delivery_unknown` не двигает базу и блокирует новый ключ.
- `POST /imports` сохраняет хэш, размер и очищенное имя. Байты файла не пишутся. Разбор XLSX не выполняется, ответ `503 SOURCE_SCHEMA_UNVERIFIED`.
- Тело запроса не принимает `url` и `endpoint` для интеграций.
- Получатели письма должны быть в справочнике гостиницы. Домен `example.com` допускается только при `NODE_ENV=test`.

## Данные

- Письмо — plain text. Пол в письме не публикуется, он нужен только для пары DBL.
- Журнал не хранит текст письма и списки адресов. CSV экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`, табуляции и CR.
- Ошибки клиенту не содержат stack и персональных данных. SQL только с параметрами.

## Демо и рабочий UI

Демо (`npm run dev` в корне) остаётся на Zustand и `localStorage` ключа `crew-support-demo`. Это не production-контур: переключатель роли и локальные токены там допустимы только как прототип.

Рабочий интерфейс, когда его подключат, обязан:

- звать `GET /api/v1/me` и не принимать роль из клиента;
- не писать экипаж и письма в `localStorage`;
- не показывать успех отправки, пока `GET /notifications/{id}` не вернул известный итог;
- не вызывать сеть из демо-кнопок.

Пока флаг рабочего режима во фронте не включён, `src/` к API не подключён.
